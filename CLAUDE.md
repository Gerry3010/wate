# yate — project notes for Claude

Terminal emulator: Go backend + Wails v3 (system WebView) + xterm.js frontend. Linux and macOS.
Plan and rationale: `~/.claude/plans/let-s-go-fable-rosy-hollerith.md` (Gerry's machine).

## Layout
- `main.go` — Wails app; CLI subcommands (`hook`, `install-hooks`) are dispatched before the GUI starts.
- `internal/app` — Wails-bound services (`PtyService`, `ConfigService`, `LogService`, …) and window options.
- `internal/pty` — `creack/pty` sessions; `internal/wsbridge` — loopback WebSocket that streams PTY bytes
  (Wails events are JSON-IPC and too slow for terminal output; binary WS frames are the data path).
- `internal/config` — TOML config on top of embedded `defaults.toml`. Struct fields carry both `toml` and
  `json` tags (the JSON shape is what the frontend sees). `[keys.<goos>]` overrides bindings per platform.
- `frontend/` — Vanilla TS + Vite. `src/api` re-exports the generated bindings (`frontend/bindings/…`,
  regenerated by `wails3 generate bindings` / the Vite plugin — do not edit by hand).

## Commands
- `make build` (→ `bin/yate`), `make dev`, `make test`, `make lint`.
- Run a packaged build with a throwaway config: `YATE_CONFIG_DIR=/tmp/yate-cfg ./bin/yate`.
- Frontend `console.error/warn` are forwarded to the Go log via `LogService` — check stderr when the
  UI misbehaves; there is no DevTools in production builds.

## Conventions
- Keep the backend UI-agnostic; anything the frontend needs goes through a bound service method or an event.
- Pin the Wails version (`go.mod` and `@wailsio/runtime` must match).
- Tests: Go `go test ./...` for backend packages, `vitest` for pure-TS logic (layout tree, keymap, link regex).
